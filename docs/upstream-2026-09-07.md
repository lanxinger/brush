## Fork adaptations

- Preserved native MSL, the alternate rasterizer, deferred SH gradients and the
  fused SH optimizer, migrating their custom operations to the new runtime API.
- Preserved PPISP, bilateral grids, tiled appearance dispatches, loss partials,
  and the GPU minimum-scale calculation.
- Kept explicit activation of learned splat parameters when beginning a training
  step. Imported splats are created on an inner device; using `Module::train()`
  alone preserves inactive parameters and can leave their gradients disabled.
- Preserved host-device identity checks and repeated registration of the same
  WebGPU device. New explicit-device processes retain their selected device;
  the legacy lazy process entry point still resolves registration when polled.
- Kept viewer buffer reuse, deterministic dataset selection and training seeds,
  masked evaluation, and the fork's refinement/minimum-scale behavior.

The lockfile uses upstream's external dependency revisions. Its differences
from upstream are the existing fork-only workspace dependencies.

The new imported-splat regression exercised actual rendering and backward
propagation on both WGSL and native MSL. It checks parameter identities, a frozen
scale floor, and finite nonzero gradients for transforms, SH and opacity.

Browser tests used Chrome for Testing 152.0.7977.75 and the matching ChromeDriver.
They exercised exported buffer ownership, repeated same-device registration,
reuse by a second Brush instance, and rejection of conflicting devices. The
existing load-only configuration deliberately avoids testing optimizer/autotuner
behavior as part of the device-ownership contract.

Cross-target checks used the installed Rustup toolchain; the Homebrew toolchain
on the default PATH lacks its WASM target. Browser test linking also required
the Rustup toolchain's `lib` directory in `DYLD_FALLBACK_LIBRARY_PATH`.

Physical iOS runtime, full-dataset quality/performance, and hosted CI for this
local port were not measured.
