## Fork adaptations

- **Device selection.** The fork registers its own compute device and accepts
  host-owned wgpu devices. Training stays on wgpu by default on every platform,
  because with the fork's native-MSL path it matched native Metal on a real
  capture and was faster on small scenes (see below).
  `BRUSH_RUNTIME=auto` or `metal` lets CubeCL choose instead, which on macOS is
  native Metal when the GPU supports Metal 3, else wgpu. `wgpu`, empty or unset
  keeps the default, and other values log a warning. The explicit wgpu setup,
  with the fork's runtime options, runs only when wgpu is chosen.
  Host-registered devices, iOS and other platforms always use wgpu.
- **Native-MSL feature.** `brush-cube/metal` now enables Burn's `wgpu-msl`
  feature, so `native-msl` keeps selecting the MSL compiler for wgpu's Metal
  backend. The native Metal runtime always compiles MSL. On that runtime the
  feature and `BRUSH_NATIVE_MSL_*` options still gate the fork's training
  optimizations.
- **Tile intersection.** Upstream's span uses square tiles. The fork's version
  takes the tile width for columns and the tile height for row strips.
  Upstream's brute-force regression runs against both 16x16 and 16x8 layouts.
- **Rerun.** `brush-rerun/build.rs` sets `cfg(rerun)` only for a desktop target
  with the `rerun` feature. This keeps `brush-c --no-default-features` free of
  Rerun on desktop and adds upstream's mobile exclusion.
- **Vendored MCAP removed.** Rerun 0.43 no longer depends on MCAP, so the
  `vendor/mcap` zstd patch from `0a23c9ed` and its spelling exclusion are gone.
  The lockfile contains no MCAP or zstd.
- **Unused-dependency lint.** `brush-loss` uses `brush-render` only for
  Apple Silicon native-MSL switches. It is now an optional dependency, specific
  to that target and enabled by `native-msl`. The fork's `brush-bench-test`
  keeps its normal dependencies, because, unlike upstream's, it builds binaries
  and benches from `src/`.
- **Test expectation.** CubeCL now names WGSL on Metal `wgpu<wgsl-metal>`. The
  fork's compiler-selection test expects that name for portable macOS builds.

The lockfile is upstream's with the fork-only `brush-appearance` crate added.
Its other differences are the fork's workspace dependency edges.

## macOS training runtime

Upstream trains on the native Metal runtime by default on macOS. This fork
keeps wgpu: on a real capture the two runtimes were equally fast, and on small
synthetic scenes native Metal was slower. All measurements used the CLI from
this port, built with `native-msl`, on an Apple M4 Pro, with seed 7 and the
fork's default preset, in A/B/B/A order. Times are end-to-end wall clock,
including loading, evaluation and export.

### Mip-NeRF 360 garden

185 views at 1297x840 (the `images_4` scale) with the COLMAP sparse model;
every 8th view held out, 7,000 steps.

| Run | Wall clock | Steps 1,000–6,600 | Eval PSNR / SSIM | Splats |
| --- | --- | --- | --- | --- |
| wgpu | 209.79 s | 180 s | 27.007 / 0.8534 | 1,748,365 |
| native Metal | 212.29 s | 182 s | 27.004 / 0.8534 | 1,749,019 |
| native Metal | 210.96 s | 181 s | 27.019 / 0.8536 | 1,748,655 |
| wgpu | 210.47 s | 181 s | 26.997 / 0.8537 | 1,750,502 |
| upstream main (native Metal) | 338.61 s | 289 s | 26.939 / 0.8513 | 1,747,858 |

The steady-state replay of the first run's 1.75M-splat checkpoint
(`brush-checkpoint-replay`, 8 views, 8 warmup steps, 20 samples of 8 steps)
also tied. Median step times were 41.38 and 41.44 ms on wgpu, and 41.38 and
41.30 ms on native Metal. The replay binary does not log its device; it uses the
same `burn_init_setup` selection as the CLI, whose Metal runs logged
`Cube(Metal(DefaultDevice))`. On this capture the fork was about 1.6x faster
than upstream main at equal quality and splat count.

### Synthetic scenes

Procedurally raycast scenes of 24 views, 3,000 iterations each. At this scale
per-dispatch overhead dominates, and native Metal was slower.

| Scene | Native Metal (`auto`) | wgpu (default) |
| --- | --- | --- |
| 160x160, random init, preset on | 12.26 s, 11.47 s | 8.88 s, 8.54 s |
| 160x160, random init, preset off | 14.52 s, 13.46 s | 11.93 s, 12.07 s |
| 512x512, random init, preset on | 17.85 s, 16.08 s | 15.42 s, 15.21 s |
| 160x160, 20k-point init, preset on | 13.55 s, 13.46 s | 12.62 s, 12.81 s |
| 512x512, 20k-point init, preset on | 15.35 s, 15.92 s | 13.96 s, 14.71 s |

An earlier first Metal run took 17.46 s, which includes a cold kernel cache.
Both runtimes reported native f32 atomic add, so the gap is not a fallback to
compare-and-swap. Quality matched within run-to-run variation, for example
PSNR 32.11–32.17 on Metal and 32.10–32.13 on wgpu for the 160x160 point-cloud
scene. Splat counts were within 1%.

### Synthetic scenes compared with upstream main

The same scenes were trained with upstream's own CLI at `d43bd1e6`, which uses
native Metal on macOS and has none of the fork's optimizations. Each binary was
warmed once per scene before timing.

| Scene | Upstream main | Fork, wgpu | Fork, native Metal |
| --- | --- | --- | --- |
| 160x160, 20k-point init | 22.81 s, 22.86 s; PSNR 31.38–31.52 | 12.62 s, 12.81 s; PSNR 32.10–32.13 | 13.55 s, 13.46 s; PSNR 32.11–32.17 |
| 512x512, 20k-point init | 22.48 s, 22.61 s; PSNR 34.42–34.47 | 13.96 s, 14.71 s; PSNR 34.85–34.92 | 15.35 s, 15.92 s; PSNR 34.89–34.90 |
| 160x160, random init | 12.95 s, 12.60 s; PSNR 19.33–19.46 | 8.10 s, 8.16 s; PSNR 27.48–27.73 | 11.08 s, 10.66 s; PSNR 27.66–27.76 |

Without an initial point cloud, upstream reached only about 24k splats against
the fork's 76k. Upstream's `create_random_splats` still samples `-depth` in
camera space, which places the initial splats behind the cameras; the fork
fixed this in `7c8e7721`. The options the two CLIs share have identical
defaults, so these rows compare the programs as shipped.

The tests above use the wgpu test device. For the Metal row, the four
`brush-bench-test` suites temporarily took their device from
`brush_process::burn_init_setup()` with `BRUSH_RUNTIME=auto`, which resolved to
`metal`. The edit was reverted after the run.

The new tile regression checks 4,000 random splats per layout against a
brute-force minimum over each tile. Both the 16x16 and 16x8 layouts pass, as
does the tightened determinism check for untied depths in the large stress
test.

Not run locally: the wasm32 and iOS checks, because this toolchain has only the
host standard library; browser tests; `cargo deny` and `typos`, which are not
installed; hosted CI; and real-dataset quality or performance.
