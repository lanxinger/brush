## Compatibility details

The exact cumulative upstream patch was applied in an isolated shared clone.
Conflicts in CLI handling, dataset tests/resolution, training initialization,
masked evaluation and refinement were resolved against the fork's existing
behavior. The adapted patch was then applied to the clean main checkout.

- New serialized settings have backward-compatible defaults: units per metre
  `1`, growth start `0`, and filter strength `0.1`. Old saved configurations
  and generated `args.txt` files continue to load.
- Dataset factors must be finite and positive with a finite reciprocal;
  filter strength must be finite and non-negative. Existing validation runs
  before dataset I/O. The public CLI still rejects zero training steps, while
  direct trainer construction safely handles the degenerate case.
- Setting filter strength to zero removes an existing auxiliary floor and
  updates the initial-publication assertion. Positive strength uses the fork's
  GPU floor calculation at the loader's effective image resolution, including
  LOD. Default training behavior is unchanged.
- Unit conversion runs after format selection and initial PLY override, so
  COLMAP, NeRF/Blender, RealityCapture and resumed checkpoints share the same
  conversion. Train/eval poses, means, log scales and auxiliary floors stay in
  agreement; exports restore dataset units. A factor of one avoids extra GPU
  copies. Standalone checkpoint evaluation/replay remain in dataset units.
- Native MSL, alternate rasterization, deferred SH gradients, fused SH Adam,
  PPISP/grid compensation, host-device ownership and the C ABI are retained.
  No dependency manifests or lockfile revisions changed.

A standalone Rust harness using the exact baseline/new KB4 numerical functions
reproduced the old failure: the fitted ultrawide fixture returned 146.37 degrees
instead of 103.5. The same assertion passes with the adopted inversion. This is
a numerical reproduction using upstream's fitted fixture, not real-lens
calibration evidence.

The new GPU tests cover KB4, thin-prism and RT8 rendering/backpropagation,
growth boundaries, degenerate training lengths, configurable/disabled floors,
and scaled PLY export/import with baked floors and opacity preservation. The
two upstream refinement tests were adapted to match the fork's production
sequence: `.valid()` before refinement, then explicit lifting before the next
training step. Passing autodiff splats directly into refinement populated
optimizer state on the wrong device for the fused native SH optimizer.

A synthetic three-view millimetre dataset exercised the real CLI, extensionless
PNG loading, `args.txt`, `units_per_meter = 1000`, delayed growth, ten base steps,
and two LOD steps. Runs with the filter disabled and enabled both reached
iteration 12/12 and exported base and LOD PLYs. Readback found finite values and
positions in the original hundreds-of-millimetres range. The filtered export
round-trip regression separately checks means, baked log scales and opacity.
This smoke demonstrates pipeline behavior, not reconstruction quality or speed.
The enabled-filter smoke also passed with a freshly built CLI using only the
normal `native-msl` feature and `BRUSH_NATIVE_MSL_PRESET=1`, with validation
readbacks disabled, exercising the fork's normal optimizer path.

The unbundled native viewer launched, but computer-use tooling could not address
its window, so GUI interaction was not verified. Physical iOS execution,
browser execution, full-dataset quality/performance and hosted CI for this
fork revision were not measured.
